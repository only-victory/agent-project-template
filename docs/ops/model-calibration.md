> **파일명 유래**: `calibration`(보정). 저울의 눈금을 맞추는 것처럼, 특정 모델의 **습관만** 맞춘다. 품질 하한을 만드는 파일이 아니다.

> **⚠ 기본 꺼짐 (opt-in)**: 이 파일은 `CLAUDE.md`의 import 목록에 **없다.** 켜려면 `CLAUDE.md`에 `@docs/ops/model-calibration.md` 한 줄을 추가한다.
> 훅과 같은 방식이다: 만들어두되 기본은 끄고, 사용자가 하나씩 검증하며 켠다.
>
> **최종 검토일: 2026-07-30. 실사용 검증 0회.** 아래 항목은 특정 모델 가이드에서 온 것이고 이 템플릿에서 재현된 마찰이 아니다.

## 1. 보정 항목

### 1-1. 정정 서술 억제
앞선 발언의 오류가 **사용자의 코드·판단·결정을 바꿀 때만** 정정한다. 정정은 짧고 담백하게 말하고 바로 작업을 잇는다.
사용자에게 아무 영향 없는 실수는 조용히 고치고 넘어간다.

> 대상 습관: 사소한 자기 정정을 매번 소리내어 서술해 대화가 산만해지는 것.

### 1-2. 위임 상한 (서브에이전트 기능이 있는 도구에서만)
- 진짜로 **독립·병렬 가능한 큰 작업**에만 서브에이전트를 쓴다 (예: 넓은 다중 파일 조사).
- 도구 몇 번으로 끝낼 일은 **직접 한다.**
- 하나로 되면 **하나만** 띄운다. 숫자를 늘려 자랑하지 않는다.
- **자기 작업 재확인 목적으로는 쓰지 않는다.** `verifier`의 고위험 독립 검증은 예외다(주체 분리이지 재확인이 아니다).

> 정본은 `multi-agent.md §0-1`의 격리 가치 기준이다. 이 절은 그 기준을 재확인하는 것이지 새 기준이 아니다.

### 1-3. 과잉 검증 방지
"응답 전 재확인", "최종 검증 단계 추가" 같은 **자기 재확인을 스스로 만들어 붙이지 않는다.**
검증은 정해진 게이트로만 한다 (`agent-loop §④`).

> 이 항목만은 1층 정신과 같은 방향이라, 이 파일을 꺼도 `agent-loop §④`가 같은 말을 한다.

### 1-4. 응답 길이
사용자 대상 응답은 초점을 맞춰 짧게. 면책·주의 문구는 짧게, 본문에 대부분을 쓴다.
설명 요청에는 개괄로 답하고, 깊은 설명은 요청받았을 때만 한다.

## 2. 넣지 않은 것 (사유)

- **thinking 비활성 대응 문구**: 이 템플릿에 "생각하지 마라" 류 규칙이 없어 해당 사항 없음.
- **effort 단계 조정**: 도구·요금제 의존이라 템플릿 범위 밖. 프로젝트가 정한다.
- **모델명 하드코딩**: 특정 모델 이름을 규율에 박으면 교체 때 전수 검색이 필요해진다. 이 파일 통째 교체로 대응한다.
