# UI 토큰 (UI Tokens)

> **파일명 유래**: `UI token`. 화면마다 반복 결정되는 값(색·간격·모서리·버튼 변형)을 한 번만 정해 이름 붙인 것. 매 화면 다시 고르지 않게 하려고 이 이름이다.

> **왜 있나 (실마찰)**: PLAN이 "메인페이지를 만든다" 수준에서 멈추면, 헤더·본문·푸터 구조와 버튼 모양은 AI가 임의로 정한다.
> 이건 AI가 제멋대로 구는 게 아니라 **명세 공백의 필연적 결과**다. 게이트가 판정하지 않는 항목은 반드시 모델이 정한다.
> 해결은 프롬프트로 부탁하는 게 아니라 **파일로 고정**하는 것이다. 이 파일이 그 파일이다.
>
> **적용 대상**: UI가 있는 프로젝트만. 자동화·스크립트·내부 CLI는 이 파일 자체를 삭제해도 된다.
> 최종 검토일: 2026-07-30.

---

## 0. 규칙 (이것만 지켜도 됨)

- 이 파일이 **유일한 출처**다. 코드에 색상 리터럴(`#3b82f6`)과 임의 px 값을 직접 쓰지 않는다.
- 정의되지 않은 값이 필요하면 **이 파일에 먼저 추가한 뒤** 쓴다. 코드에서 즉흥으로 만들지 않는다.
- 값을 늘리는 것보다 **줄이는 것이 목적**이다. 선택지가 많으면 다시 임의 결정이 시작된다.
- 웹 프로젝트라면 이 파일 대신 **CSS 변수 파일 1개를 정본으로 삼아도 된다**(그게 더 강하다: 문서와 코드가 갈라질 여지가 없음).
  그 경우 이 파일은 지우고, 정본 경로를 `CLAUDE.md §3 코드 지형`에 적는다.

## 1. 색

| 이름 | 값 | 용도 |
|------|-----|------|
| 배경 | `<채움>` | 페이지 바닥 |
| 표면 | `<채움>` | 카드·패널 |
| 테두리 | `<채움>` | 구분선 |
| 본문 텍스트 | `<채움>` | 읽는 글자 |
| 보조 텍스트 | `<채움>` | 설명·캡션 |
| 강조 | `<채움>` | 주요 버튼·링크 (**1개만**) |
| 성공 / 경고 / 오류 | `<채움>` | 상태 표시 |

> 강조색을 2개 이상 두지 않는다. 두 번째 강조가 필요하면 그건 정보 구조 문제다.

## 2. 간격

4의 배수만 쓴다. 허용값: `4 · 8 · 12 · 16 · 24 · 32 · 48`

그 외 값이 필요하면 레이아웃을 다시 본다. 대개 필요한 게 아니라 눈대중이다.

## 3. 모서리

3종만 쓴다: 작은 요소 `<채움>` / 카드 `<채움>` / 원형 `<채움>`

## 4. 타이포

- 글꼴: 2종 이하 (`<본문>` / `<제목 또는 고정폭>`)
- 크기 단계: 5개 이하 (`<채움>`)
- 굵기: 3종 이하 (`<채움>`)

## 5. 버튼

**변형 3종만**: 주요(primary) / 보조(secondary) / 텍스트(ghost)

각 변형은 아래 **상태 4개를 모두** 정의한다. 하나라도 비면 구현 때 AI가 지어낸다.

| 변형 | 기본 | 호버 | 비활성 | 로딩 |
|------|------|------|--------|------|
| 주요 | `<채움>` | `<채움>` | `<채움>` | `<채움>` |
| 보조 | `<채움>` | `<채움>` | `<채움>` | `<채움>` |
| 텍스트 | `<채움>` | `<채움>` | `<채움>` | `<채움>` |

> 네 번째 변형이 필요해지면 **ADR로 남긴다**(`docs/specs/decisions/`). 변형이 늘면 일관성이 먼저 죽는다.

## 6. 반응형

분기점 **2개만** 정한다.

- 분기점: `<예: 768px · 1024px>`
- 그 사이 동작: `<예: 1단 → 2단 → 3단 그리드. 사이드바는 1024 미만에서 숨김>`
