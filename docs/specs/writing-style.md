# 문체 가이드 (Writing Style): 글 산출물 전용

> **적용 범위**: 아티클·기고·보고서 등 서술형 산문 산출물을 쓸 때만. **세션 대화에는 적용하지 않는다**(대화는 guardrails.md 대화 어투: 개조식).
> **로드 방식**: import 금지(v2.42 판정 기준: 특정 상황 전용). 글 산출물 요청이 오면 그때 이 파일을 읽는다.
> 원문 출처: 사용자 제공 문체 가이드 (2026-08-12 반영).

### 금지 패턴

**1. 강조용 단문 끊기**
- 다음 문장을 강조하기 위해 짧게 끊는 방식.

> 예시: "피로감의 가장 위험한 부작용은 따로 있다", "이 피로감이 조직 차원에서 만들어내는 결과가 따로 있다", "오히려 반대다"
> AI는 빠르고, 저렴하고, 편하다. 안 쓰는 회사가 바보다.

**2. 같은 내용 재정리하는 마무리 문장**
- 앞에서 한 말을 한 줄로 다시 요약해주는 도장 찍기.
- 같은 주장을 두 번 정리하지 말 것. 한국어로 글을 잘 쓰는 사람은 한 번 말한 것을 다시 풀어 정리하지 않음. 독자가 따라올 거라고 믿고 다음으로 넘어갈 것.

> 예시: "Innovation Theater가 쌓아놓은 피로감이 실제로 필요한 변화의 저항이 되는 구조다", "더 많이 쓰는데 더 믿지 않는다"
> "결과적으로 ~인 셈이다", "이런 구조가 동시에 벌어지는 것이다"

**3. 불필요한 인용구**
- 가상의 인용구. 사실을 그냥 서술하면 될 것을 인용 형식으로 포장하는 방식. 이는 일반적 건조한 산문으로 쓴다.
> "AI는 말만 많고 결과는 없다" 같은 패턴
> "내가 옳고 너가 그르다"라는 생각
> "여기서는 이렇다"라는 의견

**4. 출처 제시 전 안내 문구**
- 데이터나 인용을 소개하기 전에 불필요하게 예고하는 방식.
> "ManpowerGroup의 글로벌 탤런트 바로미터는 이 역설을 수치로 보여준다", "HBR도 같은 구조를 직접 짚었다"

**5. 과도한 철학적 표현, 시적 비유, 묘사 과잉**
- 사실을 전달하면 될 것을 소설처럼 묘사하는 방식.
- 문학적인 동사들
> "위에서는", "조용히 밀어 넣는다", "조직 곳곳에 조용히 쌓인다", "굳어지고 있다" 같은 패턴.
- "그 간격은 꽤 길게 남는다", "갈림길은 조용히 다가온다", "이미 시작된 변화다" 같은 패턴
- 선명하다, 쌓는다, 갈린다, 등
- 짚는다(짚었다·짚은), 멈춘다, 흐른다, "~라 이름을 붙인다"(문학적 명명) 같은 표현도 쓰지 않는다.

**6. 문장 중간에 억지 수렴 또는 반전 구조**
- 문제는 간단하다. 질문은 더 좁아진다.
- "~라는 뜻이 아니다. 오히려 반대다" 패턴. 반전을 만들기 위해 앞에서 아무도 하지 않은 주장을 먼저 부정하는 방식.

**7. 직접 관찰하지 않은 것을 현장감 있게 묘사**
- 겪지 않은 장면을 마치 본 것처럼 서술하는 방식.
- "현장에서 보면", "많이 봐왔다", "실제로 겪어보면" 같은 표현 과도하게 사용
> "임원실에서는 여전히 기대와 압박이 섞인 에너지가 있지만" 같은 패턴.
- A사의 OO는 요즘 이런 말들을 반복한다. / CEO OO는

**8. 문단의 첫 문장의 억지 요약/예고/수렴**
- 다음에 무슨 얘기가 나올지 미리 알려주는 방식.
> "이 간극을 만드는 가장 직접적인 원인이 중간 관리자다" 같은 패턴.
- "여기서 한 가지 중요한 질문이 따라온다", "흥미로운 점은", "주목할 부분은", "정리해보면", "이쯤 되면"
- 이 모든 문제는 하나로 수렴(귀결)한다.
- "~한 이유가 여기에 있다 / ~가 여기에 있다"처럼 원인·결론을 가리키며 도장 찍는 구문 금지: 가리키지 말고 바로 서술한다.
- 안내 없이 그냥 다음 문장으로 넘어갈 것.

**9. 과장된 표현 및 추상 명사 남용**
- 구체적 사실을 추상화해서 포장하는 방식.
> "집단 기억을 만든다", "특유의 반응 패턴이 자리를 잡았다" 같은 패턴.
- 파격적·압도적·획기적·치명적·혁신적 같은 말 대신 구체 수치·사실로 환원해라.
- **"~의 주소" 은유 금지**: 판단의 주소·책임의 주소·가치의 주소·최종 주소 같이 추상 개념에 '주소'를 붙이는 은유를 쓰지 않는다. 무엇이 어디로 귀속·이동하는지를 구체로 서술한다.
- **AI 과용어: 정말 필요한 경우가 아니면 쓰지 않는다**: "비대칭" (AI가 남발. 대신 무엇이 한쪽에만 적용되는지를 구체로 풀어 쓴다). 발견 시 누적.
- **'질문이 틀렸다/잘못 던졌다/어긋났다' 프레이밍 금지**: 'AI가 진짜 ~하냐'류 물음을 "잘못 던진 질문이다 / 질문 자체가 어긋나 있다 / 답할 수 없는 게 아니라 ~다" 식으로 정리하는 건 AI가 매번 쓰는 상투구다.
- **표현만 바꿔도 같은 클리셰**(예: '잘못 던진 질문' → '질문 자체가 어긋났다'도 동일하므로 금지). 질문을 틀렸다고 라벨링하지 말고, 하려는 말을 **바로 내용으로** 서술한다(굳이 다시 묻겠다면 '더 나은 질문은 ~' 처럼 건설적으로만, 원래 질문을 깎지 않는다).

**10. 영어 번역투**
- 영어 번역투를 사용하지 않는다.
> "~에 대해 → 목적격 직결"
- "~를 통해 남발 → ~로·~해서"
- "~에 있어서 → ~에서"
- "~에 의해 → 능동태"
- "가지고 있다 → 형용사·동사 환원"
- "이중 피동(되어진다) → 단순 피동"
- "~적 N 체인 → 풀어쓰기"
- 존재론적 확신, 판단 주체 설정, 조건적 결함 등 잘 쓰지 않는 명사구를 억지로 만들지 않는다.
- 연결어미 뒤에 쉼표를 찍지 않는다: "~지만," "~고," → 쉼표 없이 잇는다.
- 무생물이나 맥락상 불필요한 "그 / 그녀 / 그것 / 그들" 대명사 직역을 쓰지 않는다(영어 it·they 직역투).
- 과금 표현: billing은 "청구"보다 **"과금"**, invoice는 "청구서" 대신 **"계산서"**를 쓴다. 과금·계산이 글의 소재라 직접 지칭해야 할 때는 그대로 써도 되나, **비유로는 쓰지 않는다**: 비유가 필요하면 "비용" 같은 직선적 표현으로 바꾼다.

**11. 전문성이 떨어져 보이는 구어체 표현들**
- 박는다. 내가 파는(사는) 건, 던진다. 가른다. 살린다. 죽인다. 들이댄다. 갈아엎는다. 부순다(부순·부숴). 등 영어로는 괜찮을 수 있으나 한글로 했을 때 권위 있는 아티클답지 못한 표현.

**12. 결말 공식·당위로 닫기**
- 문단이나 글을 "~할 때다", "지금이야말로", "~해야 한다" 같은 공식·당위 문장으로 닫지 않는다. 담담한 사실·평서로 닫는다.

**13. 형식명사·형식 종결 남용**
- "~인 것이다 / ~한 것이다"로 문장 닫는 습관을 줄이고, 평서 동사로 직결한다(예: "~라는 뜻인 것이다" → 그 내용을 바로 서술).
- "~라는 점 / ~할 수 / ~라는 바" 형식명사 반복, "중요한 것은 ~이다 / 핵심은 ~이다" 식 선결론 구문을 쓰지 않는다.

**14. 결산·강조 라벨**
- "결론적으로 / 요약하면 / 정리하면 / 시사하는 바가 크다 / 주목할 만하다 / 본질적으로 / 핵심적으로" 같은 결산·강조 라벨을 쓰지 않는다.

**15. 과도한 완곡(hedging): 단언 가능하면 단언**
- "~할 수 있을 것으로 보인다 / ~할 가능성이 있을 수 있다" 같은 이중·삼중 완곡을 쓰지 않는다.
- 단언이 가능하면 단언한다. "~할 수 있다 / ~로 보인다 / ~것이다"는 진짜 추정·가능성일 때만 쓴다.

**16. 다른 출처에서 불러온 개념을 설명할 때 부연 설명 없이 뜬금없이 들어가지 않는다**
- 널리 알려진 이론이나 개념, 상식 외에 어떤 출처에서 나온 개념 등을 차용할 경우 문장에서 갑자기 앞 내용과 관계없이 부연 설명 없이 등장시키지 않는다.
- 예) 심리학에서 오토가 그랬듯이. 자기검증이론이 말했듯. 등 어떤 내용인지도 모르고 그냥 언급해 버리는 것들을 하지 않는다.

### 문장간 연결
- 문장의 나열식이 안되도록 접속사, 연결어를 필요한 곳에 넣는다.
  예) 그러나, 이를테면, 예를 들어, 하지만, 때문에, 왜냐하면, 등 접속사
- 다음이 어울리는 문장은 아래 접속어를 사용한다.
  예) 사실, 일단, 비록, 만약, 그래도, 그런데
- 앞과 자연스러운 연결을 위해 필요하면 아래처럼 사용한다.
  예) 이처럼, 이와 같이, 그와 같은, 이같은 등.
- 단, 문두 접속사 남발은 피한다. "또한 · 따라서 · 즉 · 나아가 · 이는 · 이를 통해"를 문단마다 반복하지 않는다. 연결어는 정말 필요한 곳에만 쓰고, 없어도 자연스러우면 넣지 않는다.

### 용어 사용 원칙
1. 독자에게 생소한 용어(대중에게 알려지지 않은 난이도가 매우 높은 도메인 특화 전문 용어 등)는 처음 나올 때 괄호로 간단 한글 설명.
2. 외래어 표기는 한글을 기본으로, 필요한 경우만 영어 병기.
3. 토큰, 데이터센터, 클라우드, 챗봇처럼 이미 한국어처럼 굳어진 외래어는 병기 없이 한글만.
4. GPU, API, CRM, ERP, PoC, RAG, LLM처럼 한글로 풀면 오히려 어색한 약어는 영어 그대로.
5. Microsoft, Google, OpenAI 같은 고유명사는 영어 그대로.
6. 전문용어는 **가장 일반적으로 통용되는 표준 용어**를 쓴다. 같은 개념에 표준어가 아닌 다른 용어·표기·번역이 쓰였으면 표준 용어로 바로잡는다.
7. **`%포인트`는 쓰지 않는다: 전부 `%`로 통일한다.** (예: 6.33%포인트 → 6.33%, 8.34%포인트 → 8.34%, 6%포인트 → 6%) `%p`·`퍼센트포인트`도 마찬가지로 `%`로 적는다.

### 인물명 사용 원칙
1. 이름은 first/second name 중 하나가 아닌 full name을 쓴다. 예) 애디 오스마니, 일론 머스크
   - 단, 관례적으로 한쪽 이름만 쓰는 사람들은 예외가 허용된다. 예) 트럼프 대통령은, 모차르트, 간디, 링컨, 페더러 등
2. 인물들은 앞에 형용사를 붙인다. 다만 맨 처음에 한번 붙이고 나면 그 다음부터는 이름만 쓴다.
   예) Y Combinator의 CEO 게리 탄은, 맥킨지 대표 OO는 등
3. 단, 전세계 사람들이 거의 다 아는 이미 알려진 사람들은 앞에 형용사를 붙일 필요는 없다. 예) 도널드 트럼프, 리오넬 메시, 젠슨 황 등
   나쁜 예) 미국 대통령 도널드 트럼프.
4. 인물 자체가 중요하지 않고, 이 글의 권위에 도움이 안 된다면, 간접 표현을 사용한다.
   예) OO의 한 아키텍트는, 일각에서는, 업계의 한 대표 컨설턴트는 등

### 출처 사용 원칙
1. 독자가 상식적으로 알 만한 출처는 그대로 적는다. 예) 가트너, OpenAI, 나이키, Snowflake 등
2. 대중에게 부연이 필요한 출처는 앞에 수식어를 붙인다. 예) 블로그 플랫폼 Ghost에서는, 캐나다의 대형 은행 OOO은, 등
3. 출처, 회사 자체가 너무 빈약하거나 신빙성이 없어 보이는 내용이면 간접 표현한다. 예) 한 매체에서는, 싱가폴의 한 보험회사는, 등
