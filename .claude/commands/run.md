$ARGUMENTS: 문서 트리가 선 상태에서 연속 실행해. ROADMAP 순서대로(또는 지정 영역/Phase만) 기능을 **하나씩 끝까지, 멈추지 말고 이어서** 진행해.

**시작 전 (재개 규칙)**: `docs/plans/HANDOFF.md`의 `## /run 진행 원장`을 읽어. 있으면 거기 적힌 "다음 착수" 기능부터 시작해(처음부터 다시 하지 않는다). 없으면 ROADMAP 첫 기능부터.

**기능 1개의 사이클**:
1. **정렬 재독**: `docs/specs/PRD.md`의 진짜 목표 한 줄과 이 기능의 PLAN을 **파일에서 다시 읽어**. 앞 기능에서 기억하는 요약으로 진행 금지(여러 기능을 거치며 목표가 요약되고 재요약되면 어긋난다: 정렬 드리프트).
2. PLAN 확인(spec-gate 통과 상태) → 구현 → ./verify.sh → /validate(골든셋; **화면 작업이면 verifier가 UI 라우트 채점**) → PLAN Done + 문서 동기화
3. **체크포인트**: 로컬 커밋(`git commit`, push는 아님) + `HANDOFF.md` 진행 원장에 1줄 추가(아래 서식). 세션이 여기서 끊겨도 다음 세션이 정확히 이어받는다.
   - `git commit`은 기본 권한이 ask(확인)라 첫 커밋에서 한 번 묻는다. **연속 실행을 원하면 그때 "이 세션 동안 항상 허용"을 고르면 된다.** 안전은 guard.sh가 맡는다: 스테이징에 .env·키 파일이 섞이면 권한과 무관하게 차단(exit 2). push는 여전히 ask(원격=외부 영향).
4. **1줄 보고 후 바로 다음 기능**.

**진행 원장 서식** (HANDOFF.md 안, 없으면 섹션 생성):
```
## /run 진행 원장
| 시각 | 기능 | 결과 | 커밋 | 비고 |
| 2026-08-31 14:02 | F1-1 | Done | a1b2c3d | |
| 2026-08-31 15:10 | F1-2 | 건너뜀 | - | [?] 승인자 권한 미정 |
다음 착수: F1-3
```

**멈추는 조건은 이 4개뿐** (agent-loop §1-3):
1. 비가역 작업 도달(삭제·배포·결제·마이그레이션·외부 전송) → 승인 대기. **승인이 늦게 오면 재개 전에 원장과 git status를 다시 확인**(그 사이 세상이 바뀌었을 수 있다)
2. 게이트 실패 재시도 3회 초과 또는 사람이 정한 비용 상한 도달 → 원인과 함께 보고
3. PLAN에 `[?]` 미정 발견 또는 명세 공백 → 그 기능만 건너뛰고(원장에 사유) 다음 기능 진행, 끝에 모아서 질문
4. 성공 기준 충돌·보안 판단 필요 → 즉시 중단 보고

이 4개 외에는 묻지 말고 전진해. 가역적 판단은 기본값으로 진행하고 근거를 한 줄 기록해. 질문거리는 모았다가 사이클 사이 또는 끝에 배치로 물어봐.

**끝나면**: 완료 기능 / 건너뛴 기능(사유) / 모은 질문 / 다음 착수 지점을 표로 보고. 원장의 "다음 착수"를 갱신.
